## 1. 定位

一个跑团时挂在桌面上的音乐控制板。两个形态，没有第三个：

- **悬浮球**：常驻。一枚会转的迷你黑胶，外圈进度环就是当前 BGM 的播放进度。不展开也能读到状态。
- **主面板**：工作形态。从球心为原点缩放展开。

现有的 Godot 版已经把这套交互跑通了，本方案不改产品形态，改的是**实现栈**和**在 Godot 里做不到的部分**：
透明覆盖层、自绘窗口边框、per-monitor DPI、音频总线与声部的显式控制。

---

## 2. 为什么要换原生（而不是重写一遍 Godot）

原版的痛点集中在 Godot 最弱、也最难绕开的地方：

| 现状 | 根因 |
| --- | --- |
| `transparent=true` 配了却没生效，系统标题栏与自绘标题栏同时存在 | Godot 的透明窗口 + 无边框在 Windows 上是半成品，`borderless` 根本没配 |
| 整个曲库在启动时被整文件读进内存 | `audio_loader.gd:531` 对每个文件 `get_buffer(get_length())` |
| 淡入淡出靠每帧 `delta` 累加，打开文件夹对话框（`tree.paused`）时会卡在半途音量 | 没有绝对时间轴 |
| 进度条是假的、取消导入不取消、"从头播放"开关无效果 | 调用阻塞式 `OS.execute`，且失败只写控制台 |
| 导出包 6.4 GB | `export_filter="all_resources"` 把整套音乐库打进了 exe |

骰子项目证明的正是相反的一面：**透明覆盖层 + DirectComposition + 自绘 chrome + 显式音频声部**在这条栈上是强项。
所以换栈的收益明确落在"窗口/合成/音频控制"，成本落在"UI 控件"（Godot 白送的容器、主题、拖放、CJK 字体回退都要自己写）。

## 3. 视觉语言

### 3.1 色彩：一个灰阶家族 + 两条语义色相

```
--bg-void     #0B0C0F   窗口外、凹陷
--bg-window   #14161B   面板底
--surface-1   #1A1D24   卡片
--surface-2   #20242C   抬起
--surface-3   #272C36   悬停 / 轨道
--hairline    #2C313B   1px 描边
--text-1      #E9EBEF   曲名 / 主文本
--text-2      #9AA0AC   次要信息
--text-3      #616874   三级 / 禁用
--bgm         #F2A03D   琥珀 —— BGM 的一切
--sfx         #3FD0C9   青   —— SFX 的一切
--danger      #E5544B   仅"删除"与关闭悬停
```

**两条色相不是装饰，是"这条音频走哪条总线"的信息编码。** 唱片外圈、唱盘辉光、进度条、曲目卡选中态、
电平表全部从所属列的 `--accent` 取色，所以扫一眼就知道它归谁，不必读文字。
色彩额度全部留给音频状态，其余一切保持中性——这是"看起来专业"的主要来源。

> 实现注记：原型第一版把 `--accent` 定义在 `.col-head` 上，结果唱片、进度条、芯片全部退化成灰色。
> 强调色必须定义在**整列**这一层，让整列的语义色只有一个来源。这条已经写进原型。

### 3.2 字体与圆角

- 字体：`Segoe UI Variable Display` → `Microsoft YaHei UI` 回退链。中文由 DirectWrite 按 `zh-CN` 渲染。
- 字号阶梯：曲名 20 / 正文 12.5 / 次要 12 / 标签 11 / 微标 10。**不用 13 以上做正文**。
- 圆角：卡片 8 / 面板 12 / 窗口 16。

**文本可选范围（按白名单，不按黑名单）**

产品界面**默认全部不可选中**，只有"曲名"放行。反过来列举"哪些不可选"一定会漏 ——
时间数字、栏目标题、提示小字、按钮、标签、电平表、总线状态……列不完。

- 不可选：进度条前后的时间、栏目标题、标题栏的"音乐板"、音量百分比、分类标签、
  功能开关、音效台功能键、分类芯片、"BGM 总线"这类标签、舞台提示小字、库里的元信息。
- 可选（承载曲名的地方，用户可能想复制去搜）：主台曲名、卡片曲名、音效台名、
  悬停预览曲名、标题栏状态芯片、上一首/下一首按钮、总线状态文本。
- 输入框必须保留可编辑与可选中。
- **模拟桌面之外（方案说明区、规范区、状态矩阵）不在限制内** —— 那是给人读和复制的。

附带解决一个手感问题：拖拽进度条时不会再误选中旁边的时间数字
（实测：从时间数字横拖过整条波形，`getSelection()` 为空；在曲名上拖选正常选中）。

### 3.3 动效：三档时长、两条曲线

| 场景 | 时长 / 曲线 | 说明 |
| --- | --- | --- |
| 悬停反馈 | 120ms · ease-out | 卡片抬 1px、旋钮放大。必须无感地快 |
| 拖拽落点 | 240ms · ease-out | 虚线光圈 0.86→1 并开始 1.3s 呼吸；deck 描边转为该总线色 |
| 展开 / 收拢 | 420ms · ease-out | 面板以球心为原点 0.93→1 缩放并上移 10px；球同步缩到 0.6 淡出，**两段同时进行** |
| 唱针落下 | 900ms · ease-out | 全屏最慢的一处。因为它就是"放唱片"这个动作，要让人看见 |
| 唱片旋转 | 6.5s / 圈 · linear | 3.4s 在 140px 的盘上晃眼。**暂停用 `animation-play-state`，不能摘动画类** —— 摘掉会把角度重置回 0，盘会弹回原位 |
| 悬浮球悬停 | 240ms · ease-back | 全局唯一使用回弹曲线的元素 |
| 音波图着色 | 100ms · linear | 逐条改背景色，不用宽度动画 —— 宽度动画会触发重排 |

### 3.3.1 进度条 = 低高度音波图（连续包络，不是一排矩形）

BGM 的播放进度、音效的播放进度、搜索框里的悬停预览，三处都改用**连续包络音波图**：
一条上下对称的平滑波形（像音频编辑器里的那样），已播过的着强调色、未播的压暗。
高度只用 26px（音效 18px）。

**实现上的四个要点**（每一条都是踩过坑才定下来的）：

1. **画成一条 SVG 路径，不是一排矩形。** 矩形拼出来的看着像柱状图，不像波形。
   路径用 `viewBox 400×100` + `preserveAspectRatio="none"` 拉伸到容器，
   上下包络各走一遍（下包络倒着走回来）闭合成一个对称的填充形状。
2. **已播 / 未播 = 两条同形状的路径叠加**，靠 `clip-path` 遮罩控制露出宽度。
   遮罩值写在 **inline style** 上，**样式表里绝不能再写一条 `clip-path`** ——
   CSS 属性优先级高于 SVG 表现属性，样式表那条会把运行时的值整条盖掉。
   （原型踩过这个坑：样式表里残留了一条 `clip-path:inset(0 100% 0 0)` 当初始态，
   结果已播部分从来没显示过，只剩一根播放头线在指示进度。改成只留 inline 一套机制才修好。）
   参考盒是路径自身的包围盒，而路径横向铺满整个 viewBox，所以百分比正好等于时间轴上的百分比。
   验证方式：`elementFromPoint` 在已播区命中上路径、在未播区命中底路径 ——
   `clip-path` 会影响命中测试，这是比读属性值更硬的证据。
3. **采样密度决定"像不像波形"**。56 个采样铺在 400px 上每格 7px，画出来是条平滑带子；
   BGM 用 **160**、音效用 **80**、预览条 64，才有真实音频那种细节起伏。
4. **归一化基准要用分位数，不能用最大值。** 采样一多，序列里总有离群的高点；
   拿最大值当分母会把其余全部压低，波形退化成一条细带。
   改用 **92 分位**做基准，最后再线性拉伸到 0.05–1.0，保证任何一首曲子都铺满可用高度
   （实测路径高度稳定在 viewBox 的 94/100）。

其它：

- 包络生成：白噪声 → 加权滑动平均（相邻采样因此相关，有连贯峰谷而不是孤立尖刺）
  → `pow(2.2)` 拉开对比 → 两端渐弱 → 分位数归一化 → 线性拉伸。
- 真实数据来自解码后的 PCM 包络（按时间片取峰值）；原型用曲名生成确定性假波形，
  只要求"同一首每次画出来一样"，这样切歌时波形不会跳。接口与真实实现一致。
- **进度用"遮罩"表达，不用播放头竖线**：底路径是常态灰（未播），上路径是强调色（已播），
  靠 `clip-path` 从右侧收掉未播部分。已播/未播的分界是一刀干净的竖切，不用去看一根线的位置。
- 点击与拖拽都实时更新（已实测：点 30% → 30.5%、时间 02:10；拖到 75% → 75.6%、05:23）。
- 拖动 seek 时先只更新画面，松手才真正 seek（同原来的进度条）。
- 音效台的唱片**也旋转**：虽然大多数音效只有零点几秒，但会有把一首 BGM 拖到音效台上的用法
  （比如想让某个音效台常驻一段环境音），那时不转就看不出在放。极短的音效转不了几度，
  反馈主要由音波图扫过一遍承担，两者不冲突。

全局只允许这几档。各组件不得自创节奏。

### 3.4 唱片台的几何约定（已实测验证）

唱针是全套设计里最容易做错的一处。约定如下：

- 支点在唱片右上**外侧**，`transform-origin: 50% 0`，臂朝下悬挂。
- **空闲 = 负角度（针尖摆到盘外），播放 = 正角度（针尖旋到沟槽上）**。
  CSS 正角度把悬挂臂的末端往左摆——方向反了会让空闲状态看起来像正在播放。
- 唱片必须搁在**唱盘**上，盘沿与唱片之间留一道空隙当停放位。没有这圈盘，
  针尖离沟槽只有 5px 余量，"停着"和"在放"分不出来。
- **唱片直径 140px**（原 196），整块 deck 因此从 258px 压到 192px —— 省下的高度全部还给曲库网格。
  唱针几何按同一比例等比缩放，落点比例不变（下面的实测值已按新尺寸重算）。

### 3.4.1 盘上不写字、封面当光盘、点击唱片即暂停

直径 140px 的圆放不下长曲名，在唱片上写字只是把"读不到"藏起来。所以**盘面只有图形、没有文字**。
盘面按有没有封面分两种外观：

- **有封面** → 整盘就是封面，像光盘的印刷面：圆形裁切 + 盘缘压暗 + 一圈虹彩反光 + 中心一圈细环。
- **无封面** → 黑胶：沟槽纹理 + 中心一个总线色圆点。**中心圆是灰还是琥珀/青，就是播放状态本身。**

**唱片的中心镂空成真正的轴孔**：黑胶/CD 的中心本来就是透的。
孔的颜色取唱盘的暗度，读起来是"透过去看到唱盘"而不是"贴了个黑点"。
**悬浮球相反** —— 球心放 logo 标记、不镂空（球只有 104px，镂空一个洞更像破了个口）。

**暂停不再用按钮，改为点击唱片本体**（BGM = 暂停/继续，音效台 = 停止）：

- 悬停给一圈强调色环作为**唯一**提示，不加文字（`title` 属性仍保留给无障碍）。
- 三种状态必须靠盘面自己分清，因为没有任何按钮可以看：

| 状态 | 盘面表现 |
| --- | --- |
| 空闲 | 中心圆灰、静止、唱针停在盘外 |
| 播放中 | 中心圆为该总线色、旋转、唱针落盘 |
| 已暂停 | 整体压暗（opacity .68）、中心圆转灰、唱针抬起 |

"已暂停"和"空闲"**必须**在视觉上分得开 —— 否则用户不知道再点一下会不会继续。

**悬停特效必须有门控。** 空闲时既不换手型光标也不给强调色环
（用 `.vinyl.clickable` 区分）：空盘上划过鼠标会亮，会让人以为点了有反应。实测空闲光标为 `auto`、
播放/暂停时为 `pointer`。

**暂停要停在当前角度。** 用 `animation-play-state: paused`，而不是摘掉 `spin` 类 ——
摘类会把动画重置回 0 度，140px 的盘会"啪"地弹回原位（已实测：暂停前后 transform 矩阵完全一致）。

### 3.4.2 悬浮球：图案跟着播放转，辉光跟着音频起伏

- **球内图案跟着播放旋转**：无封面时是沟槽，有封面时是封面本身，转速与主体唱片一致（6.5s/圈）。
  中心的 logo **不转** —— 它是标记，不是盘面。暂停同样用 `animation-play-state` 停住。
- **辉光强度由"当前播放位置的波形幅度"驱动**：`--amp` 取自同一份包络在当前位置的取值，
  环的 `box-shadow` 半径与球体 scale 都按它算（环：`8px + amp × 28px`；球：`scale(1 + amp × .028)`）。
  于是球真的跟着音乐起伏 —— **这是按实际音频能量来的，不是凭空造一个 BPM**。
  真实程序里把这份包络换成解码后的 PCM 即可，接口不用动。

封面来源按优先级：文件内嵌图 → 同目录封面文件 → 无（回退黑胶）。内嵌图位置因容器而异：

| 容器 | 封面位置 |
| --- | --- |
| MP3 | ID3v2 的 `APIC` 帧（原型第一版解析器只认这一种） |
| FLAC | `PICTURE` 元数据块 |
| OGG Vorbis | `METADATA_BLOCK_PICTURE` 注释（base64，需解码） |
| M4A / AAC | `covr` 原子 |
| WAV | 通常没有；可能有 ID3 块 |

同目录兜底找 `cover.jpg` / `folder.jpg`（音乐库的通行约定，命中率很高）。
实现时把解码失败当成一等结果返回，不要静默回退成"无封面" —— 那正是本项目要避免的失败隐藏。

### 3.5 长曲名的显示策略：卡片网格 + 省略号 + 搜索框内嵌预览

**信息承载方式：**

- **曲目卡与音效卡都用卡片网格**（音效名短，方块本就合适；曲目卡回到网格后一屏能看更多张）。
  卡片宽度固定，所以卡内曲名**用单行省略号**。
- **完整曲名由搜索框内嵌的预览区承担**：悬停任意曲目卡、上一首/下一首按钮，或（放了曲目的）音效台，
   **搜索框**（同一个盒子）右侧就显示 **完整曲名 → 音波图**（不再显示分类/时长/格式 ——
  那些是次要信息，挤占的是名字与波形的宽度）；移开鼠标回到提示文案。

  **顺序是"名字在前、波形在后"**：先读到"这是什么"，再看它的形状，
  符合阅读顺序 —— 反过来会先看到一团波形却不知道是哪首。
  波形宽 118px，整段包络从开头完整画出，不裁切、不滚动。

**预览区与搜索框是同一个 box，有三条硬要求：**

1. **左边的输入框任何时刻都在、都能用。** 预览区是同一个盒子右半边，
   用一条竖线分隔 —— 所以"不悬停时搜索照常可用"是结构上保证的，不靠 z-index 或 pointer-events 去补。
   （已实测：输入框与预览区同属一个 `#searchBoxBgm`，盒子高 46px，输入框 170px，预览区吃掉剩余宽度。）
2. **它是长曲名唯一的完整出口**，所以卡片的省略号是安全的 —— 信息没有丢，只是换了地方。
3. 上一首/下一首按钮接同一条预览区。按钮自身放不下长名，用 fitText1Line 缩到下限后挂悬停跑马灯，
   但完整的 83 字曲名始终能在预览区里读到。

**什么算"有效的悬停源"要卡严，否则会到处弹：**

- **上一首/下一首都为空时不弹。** 空按钮悬停弹出一个 "—" 的波形没有意义。
- **正在播放（或暂停）的音效台不弹。** 台子上的名字虽然被压成两行省略号，
  但那块区域是用来点唱片、调音量、看进度的，鼠标一划过就弹预览很吵。
  完整名字从音效库卡片悬停读 —— 那条路径一直有效。

顺带的好处：预览并进搜索框之后不再独占一行，曲库反而多出约 37px 的高度。

**各位置的兜底顺序：**

| 位置 | 基准 | 兜底 |
| --- | --- | --- |
| 卡片曲名 | 单行 | 省略号（完整内容见搜索框预览区） |
| 音效台名字 | 11px / **固定 2 行** | 行数钳制 + 省略号。这块只有约 100px 宽，不钳制的话把一首 428 秒的 BGM 拖过来会被撑成 9 行、把整排台子拉高。完整名字靠悬停台子在上方预览区读 |
| 唱片旁曲名 | 18px / 2 行框 | 缩字号到 13px → 放开高度多占一行 |
| 搜索框预览区曲名 | 12px / 2 行 | 自然换行，不截断（后面直接接波形） |
| 标题栏状态芯片 | 11.5px / 1 行 | 先吃满剩余宽度（约 900px）→ 缩到 10px → 悬停跑马灯 |
| 上一首 / 下一首 | 11.5px / 1 行 | 缩到 9.5px → 悬停跑马灯 + 右侧渐隐 |

**三条实现注记（原型里都踩过）：**

1. 省略号只出现在"卡片"和"拖拽幽灵"上，因为那里有预览区兜底；其余位置一个省略号都没有。
   **卡片这条踩过坑**：`.track-name` 原本是 inline 的 `<span>`，而
   `overflow` / `text-overflow` / `white-space:nowrap` 三者在 inline 盒上**都不生效**，
   结果长曲名直接顶出卡片、把整页撑到屏幕外。必须 `display:block`
   （网格项还要 `min-width:0`）截断才会真的生效。
2. 跑马灯只在**真正溢出**时才挂（先测量内容宽 > 容器宽），否则短曲名也会跟着晃。
3. `text-overflow:ellipsis` 在**包裹 inline-block 的元素上不生效**，会变成硬切、连省略号都没有。
   这种情况要改用右侧渐隐遮罩 + 悬停跑马灯。

**代价**：极端长名在唱片旁会多占一行或让容器长高一点（实测 83 字符样本未触发兜底）。

（点唱片停止，与 BGM 的点唱片暂停统一成一个手势）、**每台独立的音量与开关**
（循环/淡入淡出竖排在左、音量竖排在右，滚轮悬停在音量条上也能调）。

**右列的信息层级**用一条 `margin: auto` 把"这首曲子是什么"和"能对它做什么"上下分开：

- 上：曲名（18px，最多 2 行）→ `[分类][格式] │ [循环][淡入淡出][从头播放]`（只读标签与开关并成一行）
- 下：`00:22 ──●────── 07:08`（时间并排在进度条两端，省掉一整行）→ `[▶][■]` + 上一首/下一首

循环/淡入淡出原本放在全局顶栏，现在并入这一行：它们是"放这首曲子时"才会想改的东西，
**跟着唱片走比放顶栏更容易找到**，顺带把右列原本 68px 的空档变成了最常用的控制区。

**总线状态条**是"音乐与音效独立"的显式表达：两条总线各有自己的指示点、名称和当前状态，
BGM 与 SFX 可以同时点亮。这是原版没有、但值得加的一处，因为它把"独立"从实现细节变成了可见事实。

## 5. 交互

| 操作 | 结果 | 为什么这样定 |
| --- | --- | --- |
| **拖曲目 → 唱片** | 落到该台播放；BGM 走交叉淡入淡出，SFX 立即起声 | 主路径。落点用呼吸光圈 + 该总线色描边，松手前就能确认 |
| **双击曲目** | BGM 库进主台；SFX 库进第一个空闲台 | 不想拖时的快捷路径。四台满则替换最早触发的那台 |
| **单击曲目** | 仅选中，不播放 | 避免"想看看是什么、结果响了"。跑团现场最怕误触发 |
| **点击唱片本体** | **BGM 与音效台都是暂停 / 继续** | 取消全部传输按钮，同一个手势贯穿两栏。状态由盘面自己表达（转 / 停转、抬针、中心圆灰或彩），悬停给一圈强调色环作唯一提示，不加文字。"已暂停"必须与"空闲"分得开 |
| **悬停曲目卡 / 上一首下一首** | **搜索框右侧**显示该曲的**完整曲名 + 音波图** | 卡片宽度固定、长名必然用省略号；完整信息由搜索框内嵌的预览区承担。输入框在同一个盒子的左半边、任何时刻都能用，所以不悬停时搜索照常可用 |
| **拖音波图（BGM）** | 拖动中只更新遮罩，**松手才真正 seek** | 连续 seek 会造成爆音。**拖拽期间必须让定时器停手** —— 否则 100ms 的进度 tick 会按旧位置重画、和拖拽预览互相抢，看起来就是"松手时闪两下才到位" |
| **拖音波图（音效台）** | 立即提交，拖动中就能听到位置变化 | 音效很短、可以当场重排自动结束定时器，不存在连续 seek 的爆音问题 |
| **音效台竖向音量 / 开关** | 只改这一台的音量；循环、淡入淡出各自独立 | 默认循环开、淡入淡出关。音效台不放"从头播放" —— 对零点几秒的音效没有意义 |
| **右键曲目** | 重命名 / 删除 / 移动到分类 | 重命名与删除二次确认；非法文件名在输入时就拒绝并说明原因 |
| **右键悬浮球** | 显示/隐藏面板 · 置顶 · 退出 | 球上不做左键菜单，左键永远是"展开" |
| **拖标题栏** | 移动窗口；双击切换最大化 | 走 `HTCAPTION`，保留系统手感与窗口吸附 |
| **滚轮** | 曲库滚动；在音量条上则调音量 | 悬停位置决定语义 |

**窗口与设置**：透明覆盖层 · 自绘无边框 · 置顶开关 · 最小化到通知区域 · 单实例 ·

## 7. 技术架构

### 7.1 分层静态库

照骰子项目的形状。上层可依赖下层，反向由 CMake 目标在编译期挡住：

```
src/core/       path_utf8 · settings_store · single_instance_guard · sha256
                atomic_file · logger · error（Failure 契约）
src/audio/      decoder（MF + stb_vorbis）· engine（XAudio2 声部池 + submix + ramp）
src/library/    目录扫描 · 分类模型 · 导入事务（staging → 校验 → 原子发布）
src/platform/   overlay_window（悬浮球）· panel_window（主面板）· dxgi/dcomp 合成
src/app/        main.cpp · application
tests/          每个模块一个 *_tests.cpp + CMake add_test
```

目标：`desktop_music_core` / `_audio` / `_library` / `_platform` / `_ui` → 一个 `MusicBoard.exe`。

### 7.2 接口契约（直接继承骰子项目）

全项目**不用异常**，所有可失败调用返回 `bool` 并填写 `Failure{code, context}`，全部 `[[nodiscard]]`：

```cpp
struct Failure { std::string code; std::string context; };

// 解码：最大的未知数，第一个 spike
[[nodiscard]] bool decode_audio_file(const std::filesystem::path& path,
                                     DecodedAudio& result,
                                     Failure& failure);

// 引擎：显式声部池，编译期上限
class AudioEngine final {
public:
    [[nodiscard]] bool initialize();
    [[nodiscard]] bool play_bgm(const DecodedAudio&, float fade_seconds, Failure&);
    [[nodiscard]] bool play_sfx(const DecodedAudio&, size_t slot, Failure&);
    [[nodiscard]] bool set_bus_volume(AudioBus bus, float linear_gain, Failure&);
    [[nodiscard]] bool seek_bgm(double seconds, Failure&);
    void update(std::chrono::steady_clock::time_point now) noexcept;
private:
    static constexpr size_t maximum_concurrent_sfx = 4;
    std::array<SfxVoice, maximum_concurrent_sfx> sfx_voices_{};
};

// 导入事务：校验源 → 复制到 staging → 再校验 → 原子发布
[[nodiscard]] bool import_audio_atomic(const std::filesystem::path& source,
                                       const std::filesystem::path& library_root,
                                       const std::string& category,
                                       ImportResult& result, Failure& failure);
```

### 7.3 音频方案

**解码**（骰子项目没有先例可抄的部分，也是唯一的新增复杂度）：

- mp3 / wav / aac / flac → Media Foundation `MFCreateSourceReaderFromURL`（系统自带，零依赖）
- ogg / vorbis → `stb_vorbis`（单头文件，最省事）

**播放**：XAudio2。与 Godot 版的对应关系：

| Godot 版的做法 | 原生做法 |
| --- | --- |
| 手搓 `bgm_players` / `sfx_players` 数组 | `IXAudio2SourceVoice` 显式声部池，上限编译期常量 |
| `finished` 信号里重新 `play()` 并补 0.3s 淡入来做循环 | `XAUDIO2_LOOP_INFINITE`，交给音频线程 |
| 每帧 `delta` 累加做淡入淡出 | 绝对时间戳 + `SetVolume` ramp，一步到位 |
| `AudioServer` 总线 | `IXAudio2SubmixVoice` 做 BGM / SFX 两条总线 |

**按需加载**：扫描阶段只收路径与元数据，**解码只发生在被播放时**。这直接解掉原版"整个曲库进内存"的问题。

### 7.4 窗口

- 悬浮球：`WS_EX_LAYERED` + `UpdateLayeredWindow`，真逐像素透明。
- 主面板：DirectComposition 合成，D2D 绘制，DirectWrite 排中文。
- 两个窗口**共享同一个 D3D11 设备**，不各建一套。
- 无系统边框，标题栏自绘，`WM_NCHITTEST` 返回 `HTCAPTION` 做拖动、`HTCLIENT` 给按钮。
- Per-Monitor V2：`GetDpiForWindow` + `MulDiv(v, dpi, 96)`；
  D2D render target 的 DPI 固定 96 并做运行时校验（骰子项目 `compact_composer_window.cpp:360-372` 的做法）。

## 8. 工程纪律（照抄骰子项目）

`AGENTS.md` 在写第一行代码前就要立好，三条持续边界原样继承：

1. **不静默回退**：失败必须返回错误码与上下文，禁止用默认值掩盖、禁止用关闭功能隐藏失败。
   —— 这条直接否掉原版的假进度条、假取消、无效开关。
2. **不擅自降级**：渲染与合成、权威状态与呈现分离；呈现层不得改写状态。
3. **不拿旧证据顶替当前验收**：旧的日志、静态截图、内部 PASS 都不能代替当前真实运行与人的视觉裁决。

配套：

- `docs/IMPLEMENTATION.zh-CN.md` 作为产品与架构单一事实源；每个增量一篇 `docs/validation/YYYY-MM-DD-*.md`。
- `path_to_utf8()` 单一 UTF-8 边界。注释里那句教训要一起抄：
  `std::filesystem::path::string()` 在 Windows 上用活动代码页，会损坏非 ASCII 路径。
  **中文曲库必然踩到。**
- 设置存储带 `schema` 版本 + 迁移 + **损坏隔离**（原文件挪走并带回原因，不静默清空）。
- 单实例守卫（命名互斥体 + 携带已有 PID），双击 EXE 只恢复面板，不起第二套音频实例。
- `WARNINGS_AS_ERRORS` 默认开；依赖锁到 commit + SHA256；`.gitignore` 一开始就把 `build/ dist/ evidence/ logs/` 隔出去。
- 打包自包含：zip 内含 VC++ 运行库、`THIRD_PARTY_NOTICES.txt`、`SHA256SUMS.txt`，当前用户免管理员。

## 10. 风险

1. **解码是唯一的新增复杂度**。骰子项目音质干净是因为它只播自己打包的 WAV（`audio_engine.cpp:83` 只认 `RIFF/WAVE`），
   全仓库对 mp3/ogg/flac 的引用为 0。所以阶段 1 必须先做，并把它做成可独立测试的模块。
2. **UI 工期**。2D 控件在 Godot 里是白送的，原生要自己写（命中测试、拖放、文本排版、滚动）。
   阶段 6 是全项目最大的工时块，不要低估。
3. **流式 vs 全量**。长环境音（雨声 10 分钟）解码成 PCM 后是 100MB 级。
   需要决定：短曲子全量解码驻留，长环境音走流式（`IXAudio2SourceVoice` 的缓冲区队列）。
   建议阶段 1 就把接口定成能同时容纳两种。
4. **热键冲突**。已定用 `RegisterHotKey`：组合键被占用时它返回
   `ERROR_HOTKEY_ALREADY_REGISTERED`，据此明确告诉用户哪一条没注册上，
   而不是让快捷键悄悄失效。不用低级键盘钩子（安全软件告警，且回调慢会被系统静默摘掉）。
5. **封面解码分散在五种容器格式里**（见 3.4.1）。它不影响播放，失败也不该阻塞播放，
   但实现上要逐个容器处理，且要把"解码失败"与"本来就没有封面"区分开。
   建议把它做成 `core` 层一个纯函数（路径 → 可选位图 + Failure），可以完全离线测，
   并在阶段 1 与解码 spike 一起做掉 —— 两者都是"读文件头 + 解析元数据"，共用同一套字节读取工具。
6. **长曲名策略的代价**（见 3.5）：极端长名会多占一行或让容器长高。
   实测 83 字符的样本未触发兜底，但真实曲库里会出现更长的，这是可接受的账，只是要知情。
