## 交付物

**`TransparentWindow` 基类。** 主面板与悬浮球踩的是同一批坑，那些约定只该有一份：

- `WS_EX_NOREDIRECTIONBITMAP` —— 少了它 DirectComposition 的内容根本看不见
- render target 的 DPI 钉在 96，缩放由窗口按显示器 DPI 做
- 必须是预乘 alpha，否则半透明边缘发白
- 不能有背景刷，否则启动瞬间闪白
- 释放顺序：DComp 相关先于 D2D 设备

子类只保留自己那份差别（窗口样式与消息处理）。

**`OrbWindow`。** 球 104px、进度环外径 124px、环宽 4px、四周再留 30px 辉光余量，
窗口 184×184 逻辑像素。四件它必须做对的事：

| 要求 | 实现 | 为什么 |
| --- | --- | --- |
| 圆外让路 | `hit_test_client` 圆外返回 `HTTRANSPARENT` | 少了这句，桌面上会多出一块**看不见的方块**吃掉点击，而且它是最顶层窗口，用户完全不知道为什么点不动 |
| 拖动 ≠ 点击 | 按下后位移超过 4px 才算拖动 | 整颗球既是拖动柄又是"展开面板"按钮，不区分的话手抖一下就以为用户想展开 |
| 不进任务栏、不抢焦点 | `WS_EX_TOOLWINDOW` + `WS_EX_NOACTIVATE` | 点一下球就把用户正在打字的窗口顶掉，是跑团现场最烦的事 |
| 位置记得住 | `WM_EXITSIZEMOVE` → 回调交出左上角 | 下次启动要落回原地 |

`hit_test_client` 是**公开**的，就是为了能被直接断言 ——
"圆外让路"靠模拟鼠标点桌面很难可靠地测，直接问窗口"这个点算谁的"才是准的。

## 设计稿的偏离（这是我改的，不是漏的）

**技术路线：设计稿写 `WS_EX_LAYERED` + `UpdateLayeredWindow`，实现用了
DirectComposition（与主面板同一条路）。** 理由两条：

1. 逐像素透明这件事已经在阶段 2 被实测过（含四个角 `alpha=0`）。
   再用一套新技术等于把已验证的东西换成一个没验证的。
2. `UpdateLayeredWindow` 每帧要把 GPU 的结果读回 CPU 位图，而球是每帧都在转的。
   124px 的球读回量不大，但那是白付的成本，而且两套渲染路径迟早会漂。

`UpdateLayeredWindow` 唯一可能更好的地方是"不依赖 D3D 也能工作"（D3D 挂了就什么都没有）。
这条被 `TransparentWindow::create_device_resources` 的 WARP 回退覆盖了。

## 重构顺带修掉的一个真实缺陷

**文档写的坐标契约在代码里没有落实。** `docs/IMPLEMENTATION.zh-CN.md` 与
`docs/validation/2026-09-16-phase2-window-spike.md` 都写着
"窗口按 DPI 设缩放、render target 的 DPI 固定 96"，但 `resize_composition_surface`
里**从来没有 `SetTransform`**。结果是：

- 96 DPI 下看不出问题（缩放系数是 1）；
- 150% / 200% 下合成表面是 1.5× / 2× 大，而绘制仍按逻辑坐标——
  内容只会占左上角一块，其余是空的。

提取基类时补上了这条变换（`scale = dpi_ / kBaseDpi`）。

**诚实说明这一条的验证程度**：本机只有一块 100% 缩放的显示器，
没法真的把窗口拖到 150% 的屏上看。补上的证据是"96 DPI 下帧图逐字节不变"
（说明补的变换在 96 下是恒等），以及代码里缩放系数与表面尺寸同源。
**125%/150%/200% 的实际观感仍未验证** —— 这与阶段 2 记录里那条"未完成"是同一件事，
现在它从"契约没落实"变成了"契约已落实但观感待验"。

## 崩在一句没有解释的 abort 上：D2D 资源必须来自 render target 自己的工厂

进度弧是这一阶段唯一的新绘制元素，它让程序在 `DrawEllipse` / `DrawGeometry` 上
直接 `abort()` —— 没有 HRESULT、没有异常、没有断言文本，退出码 3。

查的过程值得记下来，因为**每一步都排除了一个看起来很像的原因**：

1. 先加了 `_CrtSetReportMode` 把断言改写到 stderr —— 什么都没有。说明不是 CRT 断言。
2. 加 trace 逐块定位：辉光 / 环底 / 盘面 / 沟槽 / logo 全过，
   **唯独带描边样式的绘制之后再无输出**。
3. 试 A/B：`DrawEllipse` 不带 stroke style → 过；带 stroke style → abort。
   `CreateStrokeStyle` 本身返回 `S_OK`、指针有效。
4. 于是问题不在样式本身，而在**它由谁创建**。

根因：我另建了一个 `ID2D1Factory` 来 `CreateStrokeStyle`，再把它的样式交给
另一个工厂创建的 render target。D2D 对此不返回错误，直接 abort。
本文件里本来就有正确写法 —— `draw_waveform` 用的是 `target.GetFactory(...)`。

修法：几何与描边样式一律取自 `target.GetFactory()`。这也顺带去掉了那个
多余的工厂（少一份资源与一处潜在的不同步）。

同一处还修掉一个同类的隐性错误：调用 `DrawGeometry` 之前必须释放 GeometrySink
（`Open` 的文档里写明），否则同样是 abort。虽然这次它不是根因，但它确实违规了。

两条都写进了 `AGENTS.md` 的"隐蔽坑"。

## 顺带修好的三处工程问题

1. **纯虚函数不能在析构里调。** `~TransparentWindow` 原本调 `window_class_name()`
   去注销窗口类 —— 那是纯虚函数，基类析构期间虚表已不指向子类，
   症状是链接期一句"无法解析的外部符号"，看不出跟析构有关。
   现在 `create()` 时抄一份 `registered_class_name_` 下来。
2. **spike 的 stdout 之前是缓冲的。** Debug 断言 abort 时，崩溃前打印的每一行
   都会被丢掉 —— 现场只剩一个退出码。这与测试脚手架之前踩过的是同一个坑。
   现在 `wmain` 里设 `_IONBF`，并把 `_CRT_ASSERT` / `_CRT_ERROR` 改写到 stderr。
3. **拖动时用 `GetCursorPos` 而不是 `WM_MOUSEMOVE` 的 lparam。** 窗口一移动，
   lparam 的相对坐标就跟着变，累计起来会飘。

## 观感证据

| 文件 | 内容 |
| --- | --- |
| `evidence/stage3-5-orb-96dpi.png` | 播放中：琥珀辉光（幅度 55%）、琥珀进度弧 42% 带圆头、中心总线色 logo |
| `evidence/stage3-5-orb-paused-96dpi.png` | 已暂停：中心 logo **转灰**、弧与沟槽压暗 |
| `evidence/selftest-orb.txt` | 19/19 自检输出 |
| `evidence/selftest-hit-test.txt` | 主面板 5/5 自检输出 |

两态的区别是刻意做在**中心 logo 的颜色**上的：设计稿要求
"已暂停"与"空闲"必须一眼分得开，因为没有任何按钮可以看。
（空闲时 `progress` 为 0 → 没有弧；暂停时有弧但整体压暗、中心转灰。）

一个在透明窗口上必须想清楚的点：**"压暗"不等于"降低 alpha"**。
降低 alpha 会让盘面变得半透明，那看起来像破了个洞而不是变暗，浅色桌面上尤其明显。
实现是把颜色往 `--bg-void`（#0B0C0F）上混，alpha 保持 1。

一处主观取舍：盘面高光最初是 `radius 0.30 / alpha 0.055`，
出图之后看起来像一块灰斑而不是反光，改成 `0.20×0.055 / alpha 0.030`。
它现在几乎看不见 —— 这正是要的：高光的作用是"在转的时候看得见在转"，
静态帧里本来就不该抢眼。
