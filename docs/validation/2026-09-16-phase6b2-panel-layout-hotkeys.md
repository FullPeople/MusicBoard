## 两个产品决定

| 决定 | 结论 | 影响 |
| --- | --- | --- |
| 音效台数量 | **固定 4 个**（2×2） | 右列高度分配、`sfx_slot_count = 4`、不需要增删台的界面 |
| 全局快捷键 | **要做**，`RegisterHotKey`，不用低级键盘钩子 | 默认 `Ctrl+Alt+1..4`，可改可关 |

**为什么不用 `WH_KEYBOARD_LL`**（这一条写进了头文件与设计稿）：

- 低级键盘钩子会让每个按键都经过我们的回调（给系统加延迟），
  被安全软件当作键盘记录器告警；
- 更要紧的是**回调一旦慢了，系统会静默摘掉它** —— 用户以为快捷键还在，
  其实早就没了。那正是本项目最怕的失败方式；
- `RegisterHotKey` 的失败是响亮的：组合键被占用时返回
  `ERROR_HOTKEY_ALREADY_REGISTERED`，于是"哪一条没注册上"可以说清楚。

代价是注册成功的组合键会从当前前台程序手里拿走。对一个用户明确设置的快捷键来说，
这正是"快捷键"的定义。所以默认用 `Ctrl+Alt` 起手（很少撞车），并且可以整体关掉。

默认还带 **`MOD_NOREPEAT`**：按住不放时音效被连点几十次是灾难。

### 快捷键测试能测到什么、测不到什么

用消息窗口（`HWND_MESSAGE`）测，不需要桌面，所以能 headless 跑。
覆盖：注册 / 撤销 / **冲突时报出是哪一条** / 改绑定时不留下旧组合 /
id ↔ `WM_HOTKEY` 映射 / 参数校验。

冲突那一条**不依赖机器上装了什么**：同一个进程里注册两次同一个组合，
第二次必然失败。所以这个测试在任何机器上都是可靠的。

**测不到的：真的按一下键。** 那需要人坐在机器前，或者一个往系统输入队列
注入按键的工具。自动派发 `WM_HOTKEY` 只能证明我们的消息处理对，
不能证明注册本身有效 —— 而后者正是这个模块的成败所在，所以不拿它冒充验证。
测试里有一条断言如实记录了"没有人按键，所以没有收到 WM_HOTKEY"。

## 面板布局：数字从原型里量出来，不重新设计

原型的结构（`design/mockup.html`）：

```
标题栏 42
主体 ─┬─ BGM 列 (flex 1.46) ─ 列头(标题+音量+电平) → BGM 台 → 曲库(搜索框+芯片+网格)
      └─ SFX 列 (flex 1)     ─ 列头                → 2×2 台位 → 曲库
底栏 34
```

量出来的关键数字：面板 1256×788、列内边距 14/16/16、列头间距 12、
BGM 台 padding 16/18 + 唱片 160 + 唱片与信息间距 24、
音效台 2×2 gap 9 + 舞台 76 + 唱片 62、
曲库 `minmax(158px,1fr)` gap 7、搜索框高 46（输入框固定 172 + 预览区吃满剩余）、
芯片 26、卡片 badge 30 + padding 8。

把这些做成纯几何函数之后，面板里那类"看着不对"就变得可测了。
**布局测试抓出来的 5 处真实错误**，每一处都是我会看漏的：

| 错误 | 后果 |
| --- | --- |
| `layout.panel` 被 `take_top` 越切越小 | "某块是否在面板之内"这类判断全部错位 |
| 底栏没有从剩余区域里吃掉 | 两列一直伸到面板底部，**曲库压在底栏下面** |
| 音效台高只按"内边距 + 舞台"算 | 名字与音波图那一行被压成 **0 高**（原型里真发生过一次音波图消失） |
| 左侧两个按钮共用了音量条的 56 高 | 两个按钮加起来 116px 塞不进 76px 的内区，**直接跑到台外** |
| 预览区先放波形、后吃右边距 | 后吃把波形挤出去，"波形在预览区内"不成立 |

后面三处的共同点是：**同一个数值被两个不同的东西共用，或者切片的顺序错了**。
这类错误在画出来之后往往只是"看着有点怪"，很难定位 —— 而它们有精确的判定条件。

## settings schema 1 → 2

快捷键要持久化（默认值 / 用户改过的键 / 总开关），所以 schema 升了一版。
两条与既有纪律一致的处置：

- **旧文件升级时留一条 note**：`"旧设置文件没有快捷键配置，已启用默认的
  Ctrl+Alt+1..4；如不需要可在设置里关掉"`。升级之后全局快捷键会突然开始生效
  （会从别的程序手里拿走按键），用户得有机会知道。静默启用一个全局快捷键是不能接受的。
- 未知键仍然被忽略而不算损坏（有既有测试覆盖）。

### 测试抓到的两个真问题

1. **默认绑定只写在迁移函数里** → 首次安装没有设置文件，那条路根本不走迁移，
   于是**全新安装的用户拿到的是"快捷键全都没绑定"，而升级的用户反而有**。
   修法：默认值定义在结构体上（`HotkeySettings::decks` 的成员初始化），
   两条路共用一份；迁移只负责留 note。
2. **schema 升版让两个与迁移无关的用例静默变成了迁移用例**：
   `schema=1` 的 fixture 现在会触发迁移，状态从 `loaded` 变 `migrated`、
   `notes` 多一条，断言莫名其妙地红了。
   修法是不在那些用例里钉死 schema 号，改用 `current_schema_header()`
   按当前版本拼 fixture —— 这样以后每次升版都不会再牵连它们。
