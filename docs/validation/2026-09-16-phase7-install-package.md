## 五件事

### 1. 拖文件导入

把文件从资源管理器拖进窗口 → 导入到**当前选中的分类**（没选就用第一个分类，
再没有就用"默认"）。走完整的导入事务：复制进独立暂存目录 → 校验（按魔数探容器）
→ 原子发布 → 记进内存模型。

几条刻意的行为：

- **不搬用户的原文件**：导入是复制，源文件必须还在。
- 名字沿用文件自己的主干 —— 用户在别处整理好的命名不该被我们改掉。
- 已经在曲库里的文件跳过：复制一遍只会多一份同名副本。
- 不重扫曲库（重扫一次三秒会卡住界面），直接把新曲目插进内存模型 ——
  时长是导入事务刚探测出来的，可信。
- 有失败就把**第一条原因**带进状态栏。只报"导入 N 个"而把失败咽下去，
  用户会以为剩下的文件根本不存在。

自检里这一段的 11 条断言**在临时曲库里做**：写一个临时 WAV、把曲库根切到沙盒、
导入、断言文件真的落在 `BGM/中文分类/` 下、断言原文件还在、断言非音频会明确失败，
然后还原并删沙盒。**往用户曲库里写文件的测试是不可接受的**；已核实真实曲库
仍是 491 个文件。

分类名用中文是刻意的：分类名 → 路径这一段必须走 `path_from_utf8`，
直接拼窄字符串会走活动代码页（本项目栽过三次的那个坑），这条断言正好钉住它。

### 2. 通知区域与悬浮球

托盘图标是程序自己画出来的（32bpp 带 alpha 的琥珀色球），不是系统默认图标 ——
程序是单 exe 便携的，多一个 .ico 资源就多一处可能与安装包不同步的东西。

单击显示/隐藏面板，右键菜单：显示面板 / 总在最前 / **快捷键子菜单** / 退出。
标题栏的关闭按钮是"收进通知区域"而不是退出（与设计稿一致），退出走菜单。

自检里补了 5 条把它钉住：托盘图标建起来了、图标句柄有效、
**点悬浮球会展开主面板**（直接给球窗口发 `WM_LBUTTONDOWN/UP`，走的是与真人点击
完全相同的窗口过程）、再点一次仍然是展开（球的左键不做切换，与设计稿一致）。

托盘图标的**可视效果**没法自动验 —— 自检只能证明"建起来了、句柄有效"。

### 3. 快捷键改键

托盘菜单 →「快捷键」→ 点某一台 → 按下新组合键。

- 进捕获态时**先把自己的全局快捷键全撤掉**：不撤的话，用户按下的那一组可能
  正好已注册，会一边被捕获、一边把音效打响。
- 只按修饰键不算（用户还在组合键过程中）。
- **没有修饰键的组合直接拒**。一个裸字母当全局快捷键会把用户在任何程序里
  打的那个字吃掉 —— 这是真实危险，不是洁癖。拒绝时状态栏说明原因并留在捕获态。
- Esc 取消，并把原来的注册恢复回去。
- 改完立刻持久化 + 重新注册；冲突（被别的程序占用）在状态栏说明是哪一条。

### 4. 安装 / 卸载

**校验是完整性边界**（`verify_install_package`），不是可选的礼节：

| 规则 | 挡的是什么 |
| --- | --- |
| 清单每条路径必须相对、不许有 `..` | 路径逃逸（往 System32 写东西） |
| 每个文件哈希要对得上 | 包被改动过 |
| **包里不许有清单之外的文件** | 往包里塞一个会被加载的 dll |
| 包内不许有重解析点 | "校验过的"与"装下去的"是两个东西 |
| VERSION.txt 的产品名与架构要对 | 装错包（比如 arm64 包装到 x64 上） |

清单**自己不在清单里**（列了就对不上），所以它是包的信任根 ——
包内没有任何东西能验证它自己，那要靠包外的渠道（发布时公布的包哈希，
以及将来的代码签名）。这一条写在代码注释里，也写在打包脚本的输出里。

安装是**带日志的分阶段搬运**（`verified → staged → previous_moved →
candidate_published → committed`），断电后可以回滚或续做：

- 先抄完整个包到 `candidate-<版本>\`，再动 `current\` —— 换上去那一步只是两次改名，
  中间没有半成品窗口。
- 旧版本让位到 `previous\`，发布成功后删掉。
- 恢复逻辑按日志的阶段决定：`staged` 阶段中断 → 清掉候选（旧的还在）；
  `previous_moved` 阶段中断 → 把 previous 放回去；`candidate_published` → 收尾。

测试里手工造了"旧版本已让位、候选还没就位"的现场，验证恢复路径真的走通了。

注册只写 **HKCU**：装在用户目录、不需要管理员，那就不该要求提权才能卸载。
`UninstallString` 指向安装目录里那份 setup —— 卸载器与被装的版本天然一致。

卸载顺序是"先删目录、再删注册"，不是反过来：删目录是可能失败的那一步
（文件被占用），先删注册的话失败之后用户就再也没有入口重试了。

### 5. 打包

`tools/package_release.ps1`：校验构建产物 → 组装包目录 → 写 `VERSION.txt` 与
`SHA256SUMS.txt` → **对着真打出来的包跑冒烟测试** → 压 zip → 打印 zip 的 SHA256。

`tools/smoke_packaged_setup.ps1` 的 21 项覆盖：装 → 装出来什么 → 注册表项对不对
→ 装好的程序能跑 → **篡改包必须被拒**（改一个字节）→ **有未列文件的包必须被拒**
→ 卸 → 安装目录/注册表/快捷方式都没了 → **安装目录之外的用户数据没被动**。

## 端到端测试抓到的两个真 bug

这两个都是"单元测试全绿、只有真装一遍才会暴露"的类型：

### 1. 卸载把用户包里的安装程序删掉了

卸载的自我删除逻辑判据写成"我不在安装目录里"，于是
"用户从解压出来的包里直接跑 `--uninstall`"也满足条件 —— 它把用户包里的
`MusicBoardSetup.exe` 删了。症状是打包脚本跑完之后包里少一个文件。

正确判据是"**我是不是那份临时副本**"，也就是"我在不在 %TEMP% 里"。

### 2. 注册表里的中文名是乱码

`DisplayName` 写成 `std::wstring(name.begin(), name.end())` —— 那是**逐字节加宽**，
"音乐板"（9 个 UTF-8 字节）变成 9 个 Latin-1 字符。"设置 → 应用"里显示成
`???￤?????`。必须经 `utf8_to_wide`。

**更值得记的是这个 bug 为什么没被单元测试抓住**：那条断言把期望值也写成了
`std::wstring(product_name.begin(), product_name.end())` —— 两边用同一种错法，
于是相等、于是通过。这就是"拿实现和自己比"。

修法是让期望值**独立构造**：测试里直接用一个宽字符串字面量 `L"音乐板"` 去读
注册表比对。现在这条断言真的能失败了。

> 一条因为错误原因通过的断言，比一条红的更危险。

## 测试自身的一个坑

快捷键改键那段，我在用 Esc 取消捕获之后直接去测"没有修饰键的组合被拒" ——
但那时已经不在捕获态了，`commit` 因为"不在捕获态"返回 false，
于是"被拒"这条**因为错误的原因通过**，而后面两条断言莫名其妙地红。

修法是在测拒绝路径之前重新进捕获态。这条也写进了自检的注释里。

## PowerShell 5.1 的两个坑

打包脚本是 ASCII-only 源码，中文只放在包内的 UTF-8 txt 里。原因是：

- **5.1 没有 `utf8NoBOM` 这个编码名**，而它的 `UTF8` 会**写 BOM**。
  BOM 会让 `SHA256SUMS.txt` 的第一行以 BOM 字节开头，安装器的解析直接失败。
  改成经 .NET 用显式的无 BOM 编码器写。
- **5.1 没有 `[System.IO.Path]::GetRelativePath`**（那是 .NET Core 2.0+）。
  改成按包根前缀裁剪 —— 反正要哈希的每个文件都在包根之下。

另外：`Write-Host` 的输出不走 `2>&1`，`grep FAIL` 抓不到；
`+` 对两个 `[char]` 是做**整数加法**而不是拼接（`[char]0x97F3 + [char]0x4E50` 得到一个数），
所以冒烟测试里期望的中文名要用 `-join`。

## 未验证的部分

- **没有代码签名。** 包内清单没法验证它自己，所以真正的信任根只有
  "发布说明里的 zip SHA256"。Windows 会提示来源不明。这是发布前的硬门，
  不是可以糊过去的一项。
- **没在干净的 Windows 上装过。** 本机装过、卸过、装过很多次，
  但没有在"从没装过音乐板"的机器或虚拟机上走一遍。
- **没有真实用户从零开始用一遍**：选曲库、拖歌、按快捷键、改键、卸载。
  自检覆盖了这些**代码路径**，但"第一次用的人能不能自己想明白"只能靠人。
- **快捷键真的按下去**：自检能验注册/撤销/冲突/改键逻辑，
  但"按 Ctrl+Alt+1 音效真的响"需要人坐在机器前。这一条从阶段 5 起就是已知边界。
- **125%/150%/200% 缩放下的观感**（本机只有一块 100% 的屏）。
