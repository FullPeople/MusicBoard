## 顺手修掉的两个宽度估算 bug

- **`option_rects` 按 UTF-8 字节数估宽度**：中文一字 3 字节，于是"从头播放"
  被算成 166px（真实约 60px），BGM 台那一行五个开关加起来超出台面右边缘 ——
  表现就是"从头播放不见了"。改成按**字符数**估。
- 芯片裁剪区不含上下留白，选中高亮被切掉一截（用户原话"高亮的上下部分被裁剪"）。

## 实测证据

**悬停不再停顿**（`tools/measure_hover_stall.ps1`）：拿真光标在左列卡片网格上
每 40ms 挪一格，扫两遍 171 个采样点，从日志读相邻两次鼠标消息的毫秒间隔：

```
中位间隔 50ms   95分位 57ms   最大 4020ms
超过 250ms 的间隔: 1 次（那一次是两遍扫描之间的间隔，不是悬停停顿）
```

为此把日志时间戳加到了**毫秒**精度 —— 秒级时间戳看不出 100~300ms 的卡顿
（同一秒挤几条，看起来和流畅时一样）。

`tools/verify_disc_rotation.ps1` 抓同一张唱片的相邻两帧比较像素，74/3600 个采样点
发生变化（无封面时是那道跟着转的高光）→ 盘面确实随播放位置变化。

**右列仍然正常**（未破坏上一轮的修复）：20px 网格扫描 2117 点，

## 方法上的两条教训（已写进 AGENTS.md）

1. **内联 heredoc 里的中文会被 Git Bash 摸坏**。同一段锚点文本在脚本文件里能匹配，
   在 `python3 - <<'EOF'` 里就匹配不到 —— 于是断言失败、补丁没打上，而报错是
   "找不到锚点"，看起来像是我把源码记错了。**带中文的补丁脚本一律写成文件再跑。**
2. **播放历史的"当前项"比较**。原型的条件是"新的和**当前**那一条不同才入栈"，
   我一开始写成了"和末尾那条不同" —— 点"上一首"回去时正好命中末尾，
   于是被当成新歌追加，历史越点越长、"下一首"永远不可用。自检抓到的。
