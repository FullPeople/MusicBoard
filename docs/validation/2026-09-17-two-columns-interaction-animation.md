# 验收记录 · 两列曲库 / 交互动效 / 标题栏按钮 / 单实例

日期：2026-09-17
范围：用户报的三个问题（悬停无反应、拖不动卡、黑窗口+乱码）的根因修复，
加上两轮实机复核中发现的两个新故障，以及交互动效向原型靠拢的第一轮。

## 用户报的三个问题：根因与结论

| 用户描述 | 根因 | 结论 |
| --- | --- | --- |
| 悬停无反应、音乐卡拖不动 | 右列（音效库）**根本没被载入**：`snapshot.sfx` 从未读过，两列画的是同一批音乐曲目，而右列那些"音效卡"底下没有登记任何命中区域 | 已修：两列各读各的库，条目共用 `entries_` 数组并以 `is_sfx` 区分；命中编号段错开（芯片 400/500、卡片 1000/2000、搜索 300/301） |
| exe 里是乱码、常驻一个黑窗口、关掉就不能用 | 程序被编译成**控制台子系统**（PE subsystem 3），Windows 于是给它挂了一个控制台窗口；输出按 UTF-8 写进 CP936 的控制台成了乱码；关掉控制台等于关掉进程 | 已修：改成 GUI 子系统（subsystem 2，实测），输出附到父控制台或写 `%LOCALAPPDATA%\MusicBoard\logs\app-<日期>.log`；致命启动错误弹 MessageBox |
| 鼠标效果完全达不到网页版 | 悬停是一步到位的布尔（颜色瞬间跳），没有缓动、没有上浮/阴影；面板显隐没有过渡 | 本轮补上：悬停过渡 120ms、卡片上浮 1px + 三层软阴影、抓手淡入、在播卡片的三柱均衡器、面板显隐 420ms（缩放 + 上移 + DComp 淡入淡出） |

第三项是"接近"而不是"等同"：原型还有悬浮球 hover 放大（1.06）与按压回弹（.97），
球的窗口尺寸是固定的，要做需要动窗口尺寸或视觉变换，留待下一轮。

## 复核中发现并修掉的两个新故障

### 1. 标题栏三个按钮点不到（关闭 / 置顶 / 收进通知区域）

整条标题栏一律返回 `HTCAPTION`（拖动交给系统，这是阶段 2 的设计决定），
于是按钮所在位置也走了系统的"拖动标题栏"分支 —— **窗口过程收不到
`WM_LBUTTONDOWN`**，按钮画得出来但永远点不着。

发现方式：拿真实光标扫标题栏那一带，程序自己的输入日志里**一条记录都没有**
（`hit_test_client` 返回 HTCAPTION 时鼠标消息根本不进窗口过程）。

修法：窗口层先问 `Application::is_titlebar_button_point`，是按钮就返回 `HTCLIENT`，
其余标题栏区域继续 `HTCAPTION`。修完之后同样的扫描拿到
`id=4 x 1150..1174`、`id=3 x 1182..1206`、`id=2 x 1218..1242`（y≈21），
并且**真的点得动了**：点第三个按钮之后窗口确实收起来了（见单实例一段）。

### 2. 网格布局里"默认"分类的目录从来没被建过

扫描器把散放在库根目录下的文件归成「默认」分类，但那个目录不存在，
于是选中「默认」拖文件进来会报"目标分类目录不存在"。
修法：导入时把分类目录建出来（这个分类本来就在库的列表里，用户选中它就是明确指定）。

## 单实例：实机验证（两件事都验了）

只验"第二次启动没有起第二套"是不够的 —— 那可能只是启动失败。所以两件都验：

```
first pid=17204
visible panels after first start: 1
visible panels after the app's own hide button: 0     <- 用程序自己的收起按钮，不是从外面 ShowWindow
second pid=25836
second exited=True code=0
visible panels after second start: 1                  <- 第二个实例把面板叫出来了
musicboard processes still running: 1
日志：已有实例在运行（pid 17204），把它叫到前面来。
```

注意"用程序自己的收起按钮"这一条：从外面 `ShowWindow(SW_HIDE)` 会造成
"窗口藏了但程序内部仍认为显示中"，于是程序对呼出消息直接早退 ——
那是一个真实用户到不了的状态，据此得出的结论也是假的。第一版脚本就是这么写的，
第一版结果（`visible panels after second start: 0`）因此无效，已重做。

- 把文件作为音效导入成功、落在 `SFX/中文分类/` 下（沙盒里刻意不建该目录）

## 方法上的教训（都写进 AGENTS.md 了）

1. **`&` 不等 GUI 程序**，拿退出码与输出必须 `Start-Process -Wait`。
2. **`.ps1` 必须带 UTF-8 BOM**，否则 PowerShell 5.1 按 CP936 读，错位会把
   `{` `}` 吃掉，报错行号还指向一段无关注释。
3. **P/Invoke 声明 `...W` 函数要写 `CharSet = CharSet.Unicode`**，否则
   `GetClassNameW` 的结果被读成 `"M"`，看起来像"窗口不存在"。
4. **`Process.MainWindowHandle` 可能是另一扇窗口**（这里是悬浮球）。
   要按窗口类名找，并且用 `EnumWindows` 按 pid 过滤（`FindWindowW` 跨进程一直返回 0）。
5. **交互自检覆盖不到窗口过程层的命中测试。** 自检直接调 `on_left_down`，
   所以"标题栏按钮点不到"这种故障只能靠真实鼠标消息 + 输入日志发现。
   每个新交互都值得用真实输入复核一遍。
6. **测试要造用户真的能到达的状态。** 从外面 `ShowWindow(SW_HIDE)` 造出的
   "窗口藏了、状态说显示中"是到不了的状态，据此得出了假结论。
