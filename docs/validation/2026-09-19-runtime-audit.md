# 2026-09-19 音乐板运行时审查与修复

本轮以 `61c42be` 的干净工作树为起点，对照真实曲库、正式程序、原型与
`D:/Desktop/3d桌面骰子` 的原生生命周期实现进行检查。没有修改参考项目。

## 结论与范围

原有“阶段 0–7 完成”不代表产品没有缺陷。基线 CTest **24/25**，
`panel_layout_tests` 有一条实际失败；正式程序自检虽然打印 **134/134 PASS**，
进程却以 **0xC00000FD（栈溢出）** 退出。

本轮修复播放、后台队列、解码、输入与启动/退出链路。修复后 Release CTest
**26/26**，正式程序自检 **154/154，0 跳过，退出码 0**；真实窗口消息复核
**14/14**，普通退出与首次启动取消均返回 0。不能据此宣称整个产品已没有 bug。

## 根因与修复

| 问题 | 根因 | 修复后的行为 |
| --- | --- | --- |
| 自检全绿却在退出时崩溃；长时间使用后风险更高 | `draw_text_ellipsis` 每次绘制都以已带裁剪对象的文本格式创建新的省略号对象，引用链不断增长，递归释放耗尽栈 | 文本格式初始化时各创建一次省略号对象，绘制复用；普通文字显式使用无裁剪格式 |
| 多路音效卡在“正在载入” | worker 只保留最后一个音频任务，应用却同时等待多个台位的结果 | 播放队列不互相丢弃；最多一个完整 PCM 结果等待领取，对生产端施加背压 |
| 同一首分配多个台位时只有一路启动 | `take_audio` 领取即删除，其余台位继续等同一结果 | 一次解码将数据交给所有仍等待该曲目的台位 |
| 清空后又突然出声；快速换曲被旧请求盖回 | 清空没有撤销 pending 请求；即时就绪分支也没有清掉旧请求 | 清空/替换同时处理台位请求与 worker 取消令牌，旧代结果不能覆盖新请求 |
| 暂停的声部清不掉；刚请求淡入再清空又恢复 | 暂停分支绕过结束判断；pending_start 可重新开始已停止时间线 | 暂停中或尚未起播的停止立即释放；同步清空 UI 与待播状态 |
| 不同音频换曲后时长、速度、声道异常 | 源声部无条件复用上一首的采样率与声道格式 | 验证新格式后销毁旧声部，按新格式创建；PCM 在 `DestroyVoice` 返回后才释放 |
| seek 到 80% 后只循环前 80% | 原实现尾段播一次、前缀无限循环，并没有整曲循环 | 一个缓冲包含完整 PCM，`PlayBegin` 指定起播点，循环区域仍覆盖整首 |
| 关闭“从头播放”后重复投放暂停曲目没有声音 | 只清了界面的暂停标志，没有恢复引擎 | 明确调用引擎 resume，保留位置 |
| 音效快捷键播放左侧音乐 | `WM_HOTKEY` 从 `bgm_.visible` 取下标，没有遵循台位分配 | 优先该台待播/已分配曲目，其次右列选中或首条音效 |
| 启动/悬停时整首 PCM 解码与起播争抢 | 启动预热整库；悬停还额外请求完整 PCM | 启动只扫描元数据；波形按需分块提取，只有播放保留整首 PCM；播放可取消预览提取 |
| 后台解码 COM 生命周期不正确 | COM 初始化放在进程级静态初始化中，只初始化第一个调用线程 | 参考骰子的 RAII 模式，每次后端调用在当前线程建立/配对 COM，MF 保持进程级配对 |
| 解码失败缺少原因，坏帧可能被静默跳过 | worker 丢弃 Failure，MF 忽略 buffer 转换/Lock 错误，EOS 分支先退出 | 原始文件路径/错误码穿过 worker 上送；MF 显式检查 buffer 操作并处理末尾样本；Vorbis 检查真实错误码 |
| 音量/进度拖出窗口后粘住；Esc 无法取消拖动 | 只有卡片捕获鼠标，缺少捕获丢失/取消处理 | 滑块与进度捕获鼠标；释放、丢失捕获、失焦、收起和 Esc 均结束手势 |
| 部分滚动卡片拦截网格以外输入，分类标签偏移 | 绘制做了裁剪而 HitMap 未裁剪；芯片重复加上下留白 | 命中矩形与网格相交；芯片从布局已计算的位置开始 |
| 新装后只能看错误提示，要求用户手编设置 | 未选择曲库直接启动失败 | 第一次启动显示原生文件夹选择器；取消正常退出；中文路径一直使用宽字符 |
| 窗口回调生命周期超出 Application | 主面板保存在全局 unique_ptr，应用销毁后它仍可能持有 app 引用 | 应用析构前销毁实际窗口、停止计时器并解除回调；WM_NCDESTROY 清除 HWND/user data |

窗口销毁顺序是独立查出的生命周期缺陷。最初怀疑它解释退出崩溃，但修复该顺序后
栈溢出仍然复现；调试栈确认真正触发无限释放的是 DirectWrite 省略号对象链。
没有用“加大栈”“忽略退出码”或“跳过析构”绕开崩溃。

音频缓冲的依据为微软的
[XAUDIO2_BUFFER 合同](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/ns-xaudio2-xaudio2_buffer)
与 [DestroyVoice 生命周期合同](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/nf-xaudio2-ixaudio2voice-destroyvoice)。
参考项目具体阅读了 `src/platform/com_apartment.cpp`、悬浮球工作区/DPI 处理、
主面板和应用生命周期代码；没有整体移植骰子的产品逻辑。

## 审查发现的产品剩余项

这些是当前代码中的真实缺口，不应继续包含在“全部完成”的叙述里：

- URL 导入后端及测试存在，但 `Application` 没有接入 URL 输入与进度/取消界面。
- 分类管理、曲目重命名/移动/删除有库层 API，正式右键入口目前仍直接播放，管理界面未接齐。
- BGM 当前换曲是旧曲停止、新曲淡入；完整双声部交叉淡化尚未接通。
- 曲库丢失后的图形化重选、运行中刷新/跨目录切换、多显示器热拔插及混合 DPI 仍需产品验收。
- 长时间播放、切换系统音频设备、真人听感与拖拽手感尚未验收。本轮不声称无爆音或低延迟已达某个阈值。

本轮没有安装、上传或发布产品。旧 `dist` 安装包不能作为这些修复的交付证据；
当前可体验入口为新构建的 `build/windows-x64/Release/musicboard.exe`。
