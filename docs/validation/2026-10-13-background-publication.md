# 后台入库与真实跨盘验证

URL 下载完成后的内容探测、入库和播放准备均在后台顺序执行。主线程只读取进度与终态，取消发布时也不等待复制线程。

跨盘入库在目标分类中写入独立临时文件，核对大小后再原子改名；复制期间不出现可播放的半成品。目标已存在同名文件时不覆盖。取消复制会撤销临时文件，保留暂存源；只有成功发布且验证有效后才清理暂存源。失败原因及清理警告保留供界面查看。

## 实际文件验证

测试直接调用 Windows 复制回调和产品入库事务，源目录在 C 盘，目标在 D 盘。每次生成 64 MB WAV，并预先放置一个同名保护文件。输入、结果与报告均属于测试隔离目录。

`tools/verify_cross_volume_import.py` 的报告为 `artifacts/cross-volume-tests/82a03bf0331e48cb965e0f2ea24daa96/report.json`：

- 完整复制：66 次回调、67,108,908 字节、109 毫秒。复制后摘要与源一致，同名文件原样保留；复制期间没有提前出现音频文件，没有残留临时文件。
- 取消复制：复制到 8,388,608 字节时取消，9 次回调、31 毫秒。没有音频半成品或临时文件，源摘要与原值一致，同名文件原样保留。

默认系统 TEMP 实际位于 D 盘，最初使用默认 TEMP 的试验没有触发跨盘复制，未计入上述跨盘结果；后续明确指定 C 盘目录重测。

## 实际界面响应

真实 Windows 窗口经本地 HTTP 下载同样的 64 MB WAV，设置与暂存在 C 盘，曲库在 D 盘。窗口每隔约 10 毫秒接收一次同步消息，以高精度时钟记录处理等待。

| 程序 | 消息次数 | 最大等待 | 取消下载响应 |
| --- | --- | --- | --- |
| 0.3.1 已有候选，入库同步执行 | 173 | 97.162 毫秒 | 47 毫秒 |
| 当前后台入库构建 | 179 | 1.797 毫秒 | 31 毫秒 |

两次均保留有效离线文件，摘要与 HTTP 样本完全一致。新构建观察到实际入库百分比 93% 和 100%，复制时窗口仍响应。报告分别在 `build/windows-x64/link-ui-probe/7a86f35b66164ee582377dbd794d3573/report.json` 和 `build/windows-x64/link-ui-probe/f42d27fea77242b6bdc000cd4943d795/report.json`。这证明本机该输入消息场景的改进，不代表所有机器、网络存储或图形帧率的验收。

当前最终构建另以真实窗口导入 997 Hz 生成音频并自动播放：实际 WASAPI 振幅峰值 0.04003、基线 0，检查通过，取消响应 47 毫秒。报告在 `build/windows-x64/link-ui-probe/e0943db423e74342a40f1c36ec555b15/report.json`。只保留数值，没有保存桌面录音。

完整构建通过，28 组检查通过，20.64 秒。测试配置和暂存源隔离目录已清理。源用户曲库没有参与测试。
