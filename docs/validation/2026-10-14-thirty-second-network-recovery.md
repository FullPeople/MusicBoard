# 30 秒断网后的恢复候选

公开 0.3.4 的原生解码器在独立生成的 WAV 和 MP3 来源中都复现同一问题：首次连接中断后，HTTP 服务保持 30 秒不可用；播放器在 20 秒没有收到音频时提前结束。各 16 项既有检查有 4 项失败，原失败报告保留，没有改变断言或时限。

候选保持读取操作的 15 秒超时，允许有限的网络错误和临时 HTTP 状态重试，并将无音频恢复窗口限制为 60 秒。没有收到音频时仍会明确失败；用户停止或取消时不等待整个恢复窗口。401、403、404 等永久性错误不加入临时状态重试表。相关参数按随附媒体工具的实际支持项和 [FFmpeg 官方 HTTP 协议说明](https://ffmpeg.org/ffmpeg-protocols.html#http) 核对。

在同一 30 秒故障条件、原有 110 秒测试时限和全部原生断言下，WAV 与 MP3 各 16 项全部通过。实际断连和带偏移重新请求均有 HTTP 记录；检查包含顺序解码与准备后续流的 PCM 一致、两秒有界缓存、提前结束拒绝、真实 XAudio2 供音、停止和取消的及时响应。

证据为发行机器的 `music-long-outage-034/1a12a2021cb54dac8aa765232a26b0db`（失败）和 `music-long-outage-candidate/11a90c1b62394d8ab238575fa08366cb`（候选通过）。候选基于 `9e4d443d4dd08f77bc41d6c7dab521360538f809` 的独立工作树，报告保留探针摘要和实际补丁摘要。

这是原生解码与播放检查，尚未替换公开 0.3.4 安装包，也不能代表完整应用的所有平台链接、永久断网、链接过期、付费或登录来源。完整应用构建、实际导入播放、安装和公网更新仍须单独完成。
