# MusicBoard 0.3.6 Windows 安装与更新

0.3.5 已有单文件安装包、菜单更新和启动后自动检查，但安装外壳仍是旧单页，常驻运行不会再次自动检查。
本次将 Windows 版本提升到 0.3.6，保留原签名更新器和公钥，新增独立安装向导和常驻检查调度。
macOS 包与播放功能不属于本次改动范围。

## 安装向导

- 六页流程包含许可、完整程序内容、安装目录与桌面快捷方式、确认、进度和完成后启动。
- 中文与英文成对；只有一个实际必选程序模块，媒体工具、其许可证和对应源码资料完整保留。
- 批量重绘、局部刷新、后台空间查询；进度来自实际归档字节、提取字节、核对文件、复制字节、登记和清理。
- 只有安装成功并清理本次暂存文件后才显示 100%；校验与提取阶段允许取消。
- 当前用户安装，无需管理员权限。以后静默更新沿用登记目录和桌面选择。
- 已安装后不支持直接迁移到另一目录：安装前提示沿用旧目录，或先卸载再选择新目录；卸载保留曲库和设置。
- 安装与卸载共用每目录跨进程锁；冲突明确失败，不允许同时写同一候选目录。
- 自选目录卸载命令带完整路径，登记失败返回失败；旧卸载器不得删除其他位置的新登记。

## 持续更新

安装版启动 10 秒后首次探测，之后每分钟在后台判断是否到期，每 24 小时最多自动启动一次签名检查。
手动菜单请求不等待每日额度，且与自动检查共用进程保护。更新器及临时 worker 通过命名 Job 跟踪，
不会因原启动器退出而重复打开。退出音乐板只结束自身调度线程，不终止用户已经打开的更新。
便携版不自动启动安装更新。

原更新器仍在下载前验证 RSA-PSS/SHA-256 清单签名，下载后检查长度和摘要，安装前再次核验。
发现更新后仍需用户确认下载与安装；安装前应退出音乐板。网络检查失败沿用原更新器的每日额度策略，
需要立即重试时可使用菜单。调度测试涵盖睡眠、前后调时和失败重试，不代表等待了实际 24 小时。

## 已执行验证

- Release 原生应用、安装后端、向导和提取探针构建，项目代码使用 `/W4 /WX /utf-8 /permissive-`。
- `core_tests`、`settings_tests`、`sha256_tests`、`update_schedule_tests`、`install_transaction_tests`、`product_registration_tests` 通过。
- `verify_wizard_staging.py`：23 项实际提取、逐文件摘要、原清单、CRC、重复路径、路径穿越、取消、拥有权和重解析点检查。
- `verify_installer_wizard.py`：22 项最终单 EXE 新装、实际 0.3.5 运行时升级、程序版本、完整媒体载荷、
  私有登记与快捷方式、同版本选项保留、已安装卸载器、错误清单拒绝、并发拦截、实时进度及清理检查。
- 测试使用独立安装目录、独立 `LOCALAPPDATA/TEMP/TMP`、私有 HKCU 产品键和快捷方式；曲库为人工测试文件。
  0.3.5 基线由实际公开完整包执行安装事务建立，没有调用会改写真实产品登记的旧安装器。
- 完整安装首次发现后端缺少长路径声明，深层临时目录会误报缺少插件文件；增加声明后同样的深路径检查通过。
- 复用的 0.3.5 原始 ZIP 在拆包前核对公开固定 SHA-256，所有原文件核对清单后才替换本次程序和后端。
  原 `FullToolsUpdater.exe` 与媒体运行时未改变；新原生组件、许可与清单重新封装。

## 验收边界

未运行电脑控制或自动点击安装界面。安装界面实际手感、真实多显示器切换、用户设备播放与更新窗口操作仍待用户验收。
静默安装和纯调度测试不能替代这些观察。未重新宣称所有音乐平台均已实测；此前播放记录保留在网络验证文档中。
源码云端检查、公开发布回执、官网和更新清单验证由此次发布证据分别记录。
